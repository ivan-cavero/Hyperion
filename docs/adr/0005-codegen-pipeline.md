# ADR 0005 — Data → codegen pipeline for the protocol

- Status: **Accepted**
- Date: 2026-08-02

## Context

Mojang ships frequent releases (26.x versioning). Writing the protocol,
registries, and NBT by hand per version is unsustainable (weeks per release).
Valence and Pumpkin validate the pattern: extract data from the Mojang jar to
JSON and generate Rust code with `build.rs`.

## Decision

The protocol, registries, and data formats are defined in **versioned JSON
extracted from Mojang** (data generators + jar extractor) and Rust code is
generated by codegen (`build.rs`). None of that code is written by hand.

## Consequences

- Each Mojang release = a new data commit + regenerate (days, not weeks).
- LLMs can assist with diffs, **always** verified by fuzzing +
  diff testing against vanilla (generated data is not trusted to AI without
  verification).
- `minecraft-data` (community) is used only as a secondary reference, not as a
  primary source (it lags Mojang and is partial).
- Codegen generates parsers → the fuzzing surface (Phase 1) covers everything
  generated automatically.
